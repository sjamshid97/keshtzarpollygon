# ابزارهای ساخت و آزمایش

این پوشه فقط برای **توسعه** است. خودِ برنامه (`index.html`) به هیچ‌کدام از این‌ها نیاز ندارد و
کاربر هرگز چیزی از این پوشه را باز نمی‌کند. هیچ دادهٔ واقعی این‌جا نیست؛ همهٔ داده‌های آزمایش ساختگی‌اند.

## هر انتشار، به ترتیب

1. تغییر را در `index.html` (و اگر لازم بود `sw.js`) بدهید.
2. شمارهٔ نسخه و نسخهٔ نمایشی:

   ```
   python3 tools/release.py 2.6.2
   ```

   این دستور `APP_VERSION`، نام کش در `sw.js` و خط نسخهٔ `README.md` را یکی می‌کند و `demo.html` را از نو می‌سازد.
3. آزمایش‌ها (بار اول: `cd tools && npm install`):

   ```
   node tools/lint.mjs               نام‌های تعریف‌نشده و تکراری در اسکریپت
   node tools/tests/run.mjs          همهٔ آزمایش‌های مرورگری (حدود ۵ دقیقه)
   python3 tools/release.py --check
   ```
4. بعد از تأیید صاحب برنامه: commit، PR و ادغام در `main` (GitHub Pages خودش منتشر می‌کند).

## فایل‌ها

| فایل | کار |
|---|---|
| `release.py` | یکی‌کردن شمارهٔ نسخه در همه‌جا + ساخت `demo.html` + بررسی |
| `build_demo.py` | ساخت `demo.html` از `index.html` (حافظهٔ جدا، دادهٔ ساختگی، بدون سرور) |
| `demo/seed.html`، `demo/bar.html` | دادهٔ ساختگی و نوار «نسخهٔ نمایشی» |
| `syntax_check.py` | بررسی نحوی اسکریپت‌ها با `node --check` |
| `lint.mjs` | بررسی ایستا با ESLint |
| `tests/h.mjs` | ابزار مشترک آزمایش: کروم بی‌صفحه، سرور کوچک فایل، زدن دکمه‌ها |
| `tests/sb.mjs` | سرور ساختگی همگام‌سازی (به اینترنت وصل نمی‌شود) |
| `tests/dev.mjs` | «دستگاه»های آزمایشی و نسخهٔ قبلیِ برنامه از تاریخچهٔ گیت |
| `tests/t_*.mjs` | آزمایش‌ها؛ هر فایل یک موضوع |
| `tests/shots.mjs` | عکس از چند صفحه برای نگاه با چشم (`tests/out/shots`) |
| `installer/` | ساخت فایل نصب ویندوز |

## آزمایش‌ها چه چیزی را می‌سنجند

- `t_outputs` — یک سناریوی یکسان روی نسخهٔ قبلی و نسخهٔ تازه اجرا می‌شود و همهٔ خروجی‌ها
  (GeoJSON، KML، CSV، JSON، Word، چاپ، پشتیبان‌ها) **بایت‌به‌بایت** مقایسه می‌شوند.
- `t_restore`، `t_sync_delete` — بازیابی از پشتیبان، حذف، و این‌که هیچ پروژه‌ای دوتا نشود.
- `t_sync_basic`، `t_mixed` — همگام‌سازی دو دستگاه؛ نسخهٔ تازه کنار نسخهٔ قبلی.
- `t_edit` — نوشتن مختصات و پرسش پیش از هر حذف.
- `t_quiet` — همگام‌سازی خودکار هنگام نوشتن بازدید هیچ پیام یا پنجره‌ای نشان نمی‌دهد.
- `t_file` — برنامه وقتی از روی فایلِ روی کامپیوتر باز می‌شود (همان چیزی که فایل نصب ویندوز می‌گذارد).
- `t_upgrade_file` — «نصب روی نسخهٔ قبلی»: نسخهٔ قدیمیِ نصب‌شده داده می‌سازد، فایل برنامه در همان مسیر با نسخهٔ تازه
  عوض می‌شود و باید همهٔ داده، عکس، امضا و تنظیم همگام‌سازی سر جایش بماند؛ همچنین کامپیوتری که ده روز باز نشده.
  نسخهٔ قدیمی در مخزن نیست و از داخل فایل نصب قبلی بیرون کشیده می‌شود (پایین را ببینید)؛ اگر نباشد این آزمایش رد می‌شود.
- `t_misc`، `t_fullbackup`، `t_offline`، `t_demo`، `t_smoke` — بقیهٔ بخش‌ها.

برای آزمایش «دو نسخه کنار هم»، شمارهٔ commit نسخهٔ منتشرشدهٔ قبلی در `tests/dev.mjs` (`BASE_REV`) نوشته شده است؛
بعد از هر انتشار آن را به‌روز کنید.

## فایل نصب ویندوز

برنامهٔ نصب‌شده با فایل نصب، از روی «فایلِ روی کامپیوتر» باز می‌شود و **خودش به‌روز نمی‌شود**؛
برای هر نسخهٔ تازه باید فایل نصب تازه ساخت. داده‌های کاربر داخل مرورگر است و نصاب به آن دست نمی‌زند.

```
python3 tools/installer/build_installer.py --base _local/base/فایل-نصب-قبلی.exe --out windows-installer
```

- `--base` فایل نصبِ یکی از نسخه‌های قبلی است (هر کدام). بدنهٔ اجرایی از آن برداشته می‌شود و فقط محتوایش عوض می‌شود.
  این فایل در مخزن نیست (فایل اجرایی در مخزن نگه‌داری نمی‌شود)؛ باید از صاحب برنامه گرفته شود.
  جای پیشنهادی: پوشهٔ `_local/base/` (در گیت نمی‌رود).
- ابزار پیش از ساخت، خودش را می‌آزماید: فایل پایه را از روی محتوای خودش دوباره می‌سازد و باید بایت‌به‌بایت همان شود.
- `installer/install.ps1` اسکریپت نصب است (UTF-8 با BOM و پایان خط CRLF). نکته‌های مهمش:
  - میان‌بر با نام انگلیسیِ موقت ساخته و بعد به نام فارسی «تغییر نام» داده می‌شود (ذخیرهٔ مستقیم با نام فارسی روی ویندوز کاربر شکست خورده بود).
  - اگر میان‌برِ قبلیِ همین برنامه پیدا شود، همان مرورگرِ قبلی به کار می‌رود (دادهٔ کاربر داخل همان مرورگر است).
  - گزارش کار: `%LOCALAPPDATA%\SeedCoordinates\install-log.txt`
- بیرون‌کشیدن محتوای فایل پایه (برای آزمایش `t_upgrade_file`):

  ```
  python3 tools/installer/build_installer.py --base _local/base/فایل-نصب-قبلی.exe --extract _local/base
  ```
- بررسی‌های بدون ویندوز:

  ```
  pip install tree-sitter tree-sitter-powershell speakeasy-emulator
  python3 tools/installer/ps_check.py tools/installer/install.ps1
  python3 tools/installer/emu_check.py --base _local/base/فایل-نصب-قبلی.exe --new windows-installer/00-windows-vX.Y.Z.exe
  ```

  اولی نحو و نام‌های اسکریپت را می‌سنجد (فرمان، پارامتر، متغیر)؛ دومی بدنهٔ اجرایی را در ویندوزِ شبیه‌سازی‌شده اجرا می‌کند.
  **هیچ‌کدام اسکریپت نصب را اجرا نمی‌کند و جای آزمایش روی ویندوز واقعی را نمی‌گیرد.**
- فایل نصبِ ساخته‌شده (`windows-installer/*.exe`) را در مخزن commit نکنید.
- قاعده: دو ساختِ متفاوت هرگز یک شمارهٔ نسخه ندارند. اگر پس از دادنِ فایل نصب چیزی در برنامه عوض شد، شمارهٔ نسخه بالا می‌رود.
